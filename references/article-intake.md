# 从文章正文补充曲子

用于用户明确要求查资料、抓文章、补充或修订曲子库。普通消息生成不走这条流程。书籍也用同一套筛选标准，定位改为版本、章节或页码；目录、书介和搜索摘要只算线索。

## 先带着难题搜索

先查 scenes/README.md 与相关卡片。优先补候选卡缺失的原场景依据、用户指出不好用的表达，以及没有可用卡的类别；不要为了八类数量齐整批量造例子。

用户要找高传播表达素材时，先搜“高情商话术”“高情商说话”“说话技巧”，筛相关性后按分享数优先、阅读和点赞辅助选候选，保留实际指标与时点；高分享不等于表达有效。明确补某个难题时再用“中秋聚餐”“被问收入”“家长老师沟通”等处境词。结果混入新闻、广告或感悟时先筛除，不把热榜全量当话术。用户指定旧文时直接抓链接，不受近期热榜范围限制。给搜索服务的词用概括后的难题，不发送私人聊天或身份信息。

### 复用 RedFox，不再写一套爬虫

若已安装 title-skill，先读取其当前脚本说明。已核对的入口为 `scripts/fetch_official_account_trends.py`，使用环境变量 `REDFOX_API_KEY`，支持 `--keyword`、`--days`、`--output-format json` 和 `--output`。确认实际路径与 `--help` 后调用，例如：

```bash
python3 "$TITLE_SKILL/scripts/fetch_official_account_trends.py" \
  --keyword "拒绝饭局" --days 30 --output-format json \
  --output "$MATERIAL_DIR/search.json"
```

`TITLE_SKILL` 是实际发现的安装目录，`MATERIAL_DIR` 是仓库外的本地素材目录；先创建目录。不要把维护者机器路径当成安装条件。该脚本走 RedFox `hotArticleNew`，最多查询近 30 天，本次核对的响应含标题、摘要、作者、链接和热度，其中 summary 可能是短简介，也可能含较长对话片段，不能仅凭字段名认定已取得或未取得正文；逐条检查实际文本与完整性。只处理 `articles`，不要把不相关的热门兜底当关键词命中。参数与字段以实际安装版本为准。

有 gzh-search 时也可读取它的说明使用已有搜索入口；两者参数不同，不照搬。无可用 RedFox 或凭证时使用现有搜索工具、用户链接或提供的文件，不擅自安装或修改认证。认证、额度问题明确报告；不要输出 Key、Cookie，也不用带 Key 的命令行或报告。

## 抓正文，并检查抓到了什么

选少量相关条目先验证取文路径，再扩大批次；按原文 URL 和内容查重，转载保留当前页与原出处的区别，不把转载账号自动当作者。未知署名就写未核实。

微信公众号 URL 有 atm（source-to-markdown / anything-to-markdown）可用时，读取它的当前说明，使用已有 `scripts/url_to_markdown.py`：

```bash
python3 "$ATM_SKILL/scripts/url_to_markdown.py" "$ARTICLE_URL" "$MATERIAL_DIR/article.md"
```

当前实现复用 `opencli weixin download`；atm 是技能别名，不保证 shell 里存在同名命令。失败可换已有正文提取工具或获授权的浏览器；遇登录、验证或权限限制就保留失败记录，不绕过。无可读正文时仍可完成筛选流程与线索登记，但不能入曲。

**回读文件，不只看退出码。** 核对标题与目标文章是否一致；是否有连续正文、完整上下文和可定位段落；是否只是摘要、验证页、广告、图片占位或“赞／在看”等按钮。只有部分正文就注明范围，图里有关键对话但没识别到就注明缺失。字数多也不能自动证明正文有效。

每批本地保存搜索响应、有效正文及一份简短记录：查询词、抓取日期、标题、账号/署名、URL、实际读取范围、正文小标题或段落定位、处理结论与原因、关联 S/C 编号。状态用“线索／正文已读”；处理结论用“补旧卡／新增候选／反例／暂不采用”，不要把它们混成一个质量分数。阅读材料按[素材库约定](../materials/README.md)整理为 Markdown：阅读版移除来源杂项，出处另存索引，分析与原文分开。原始全文留在仓库外，通过忽略的 local 入口访问；公共仓库只提交来源、必要短引文与原创分析。

## 从原场景决定是否入库

阅读前后文，再回答：谁对谁说、刚发生什么、想要什么、说了什么、对方怎样回应；最后一项原文没写就注明，不能编圆满结局。作者声称有效与已观察到的结果分开。没有对话、只有立场宣言，可作为判断材料，不强制变成参考话术。

优先保留能解释表达作用的场景：怎样避免公开私事、怎样让对方有台阶、怎样不给自己新增义务。阅读量、名人署名、“高情商”标题均不能替代这个判断。原文有“下次我请”“家人生病”等说法时，分别核对未来承诺和事实前提；不想兑现或未经用户提供，就不能照搬。

用已有曲目机制查重。相同条件的新句子先修订旧卡；条件变化才加场景卡；不同表达动作才新增曲目。不得为旧的原创卡补一个书名便宣称“来自正文”：必须逐条写清原场景与迁移差别，必要时替换原例；缺证据就保持未补齐。

新增或修订卡保留：

- 原场景与精确定位；原句只作必要短引文，改写单独标明。
- 本次用户条件与参考表达；有哪些事实不能带过来。
- 最可能的一轮追问、接话代价、一个不能套用的相似情境。
- noai 实际检查的改前／改后／理由；原句合适可不改，不为润色而润色。

noai 负责自然度和保真，不替 say 决定回应策略。正文优美也不保证适合日常微信；文艺感悟、演讲段落、油腻恭维不能直接当聊天话。只有格式通过、模型自评或来源可靠，仍是候选；具体人工反馈按 CONTRIBUTING.md 登记后才能已验收。

## 交付与停止条件

按 CONTRIBUTING.md build、check 并检查受影响场景。报告实际搜索条目、正文成功与失败、采用与淘汰、新增与修订数量，给出来源及取舍。搜到多少文章不等于新增多少曲子；已读但没有好例子时，新增为零也如实交付。相同失败不反复重试，先把已读材料处理完。

交付后优先让用户对少量具体版本指出“这句愿意发／这句别扭”，保留反馈到对应卡；不要请用户给整库笼统打分，也不把一次认可推广到整首曲子。
