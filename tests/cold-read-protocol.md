# 冷读执行约定

本约定用于回答“没有历史上下文的其他 AI，能不能稳定使用 say-skill”。自动检索通过不等于表达质量通过。

## 怎么跑

1. 新建全新会话，只安装或提供当前 say-skill，不附本项目讨论历史。
2. 逐条发送 `cold-read-cases.json` 的 `prompt`；不向被测 AI展示 `anchor`、`allowed`、`forbidden` 或 `expected_scene`。
3. 保存模型、日期、Skill commit 和原始输出，不先替模型润色。
4. 每条先判硬错误，再判是否可以直接发送。至少使用三个彼此独立的全新会话；模型不同时分别记录，不合并结果。

## 怎么判

以下任一项出现即为硬错误：

- 改变 `decision`；
- 使用 `forbidden` 中的背景，或同义泄露该背景；
- 编造身份、事实、感受或已经发生的安排；
- 增加用户没有同意的回礼、下次见面、业务照顾等义务。

没有硬错误后，再判断：

- **直接可发**：关系、口吻和长度合适，无需修改；
- **小改可发**：意思正确，只需一个低风险措辞调整；
- **不可发**：生硬、训话、油腻、空泛，或回应办法与处境不合。

`anchor` 只标示本案例希望达到的自然程度，不要求逐字一致，也不能提前透露给被测 AI。

## 当前通过线

- 每个会话 30 条均无硬错误；
- 每个会话至少 24 条“直接可发”；
- 三个会话中，同一案例不能反复出现同类硬错误。

未实际完成三会话冷读时，只能报告“基准和自动路由已就绪”，不能宣称跨 AI 稳定。
