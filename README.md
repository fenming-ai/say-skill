# say-skill｜让话说得清楚、自然、有分寸，自己也不受委屈

被催婚，不想吵起来，也不想一直忍着；朋友热情邀约，想拒绝又怕扫兴；红包收也不好意思、不收又怕驳了心意；跟喜欢的人聊天，总像在谈工作。

把发生的事和你的真实想法告诉 AI，say-skill 帮你组织成说得出口、发得出去的话。有原话可以直接贴，没有草稿也能用。

它会在动笔前多想几层：你真正决定了什么；哪些背景只供理解、不该说出去；对方递来的是心意、请求、压力还是拒绝；双方是什么关系；这句话会不会引来追问、回礼或下次承诺。最后只把必要的话交给你。

它的价值体现在四件事上：

- **保住本意**：拒绝就是拒绝，不会为了显得圆滑，把答案改成“下次一定”。
- **保护隐私**：知道你为什么不想去，不等于把“最近胖了”“收入多少”等私事写进回复。
- **照顾关系**：接住对方真实递来的心意、感谢或顾虑，让对方听得懂、接得住。
- **考虑下一轮**：提前检查对方最可能怎样追问，避免一句漂亮话换来更多解释和人情债。

## 它帮你解决哪些尴尬

- **父母与亲戚**：催婚、催生、收入追问、家庭聚餐、共同出游与分工、被比较、被替你做主。
- **朋友与人情**：拒绝聚会、借钱或帮忙，接住别人的拒绝，回应“你破费了”，按真实近况送祝福，争执时暂停再谈。
- **红包与送礼**：自然收下、表达感谢、婉拒红包、处理供应商或下属送礼、回应对方推辞。
- **认识与约会**：自然接话、具体夸赞、表达好感、发出邀请、面对拒绝；也可以说“帮我泡妞”。
- **相亲与关系选择**：介绍自己、表达期待、继续了解或明确结束。
- **家长与老师**：用具体观察问清情况、回应反馈、表达异议、说明家庭会怎样配合、节日感谢、跟进孩子遇到的问题。
- **父母与孩子**：先听孩子说完，允许哭和生气，拦住打人等伤害行为，在决定不变时仍听理由，帮助孩子面对欺负并求助。
- **工作与日常事务**：请假、改期、催进度、拒绝额外任务、会议聚焦与分工、客户顾虑、发送资料、感谢具体付出和简短邮件。

当前八类共有 **41 首曲子、136 张场景卡**。未经认可的原创卡标为待重审，不进默认检索；从正文提炼的新内容先标为候选，不会因为“有来源”就假定有效。分类、数量和验收状态统一见[场景库](scenes/README.md)，可迁移的表达方法见[曲子库](tunes/README.md)。

## 先用一次

```text
使用 $say-skill。
朋友约我今晚吃饭，我想在家休息，这次不去，也不想约定下次时间。
帮我说得友好一点，不编理由。
```

一种可能的表达：

> 谢谢你叫我，今晚我想在家歇着，就不去啦。

也可以直接描述难处：

```text
帮我会说话：爸妈每次打电话都催婚，我现在一想到打电话就有压力。
我想跟他们正常聊天，但不想每次都聊结婚。
```

一种可能的表达：

> 爸妈，每次打电话都聊结婚，我现在打电话都有压力了。我也想跟你们聊聊别的，今天先不说这个，好吗？

措辞不是标准答案。它会保留你的决定与真实意思，不擅自编具体经历、答应下次，也不会替你发送。你告诉 AI 的私人背景，不会默认写进回复。你不必说得漂亮，更不必为了让对方满意委屈自己。

## 曲子库怎样让它越来越会说

角色是懂人情、有分寸、有自己立场的沟通参谋：先看关系与处境，保护用户意愿与隐私，再照顾对方的体面；不把让所有人满意作为目标。

一首曲子记录一种可以迁移的表达方法：**什么情况下用、想表达什么、容易怎么说坏、可以怎样说、为什么、什么时候别用。**

同一方法用在催婚、邀约或工作中，就新增场景卡，不重复建曲。曲子讲方法，场景卡写具体条件、参考表达、追问和不适用情况，分别使用稳定的 S 编号和 C 编号。

资料包括蔡康永、刘墉的公开正文片段、作者文章、社交平台讨论，以及本项目原创场景；每条分别标注来源，不把原创表达冒充书中摘句。正文提炼优先保留原场景、关键短引文和出处，再做原创迁移；没读到正文就不凑数量。候选可供参考，不代表效果已经获得人工认可；待重审仅作维护草稿。

用户提供并认可的[红包表达 C0101](scenes/cards/C0101.md)已作为正向对照：收下更看重的心意，同时拒收钱。认可仅限主表达，整卡的解释、追问和迁移仍待验收；不会因为一句话获认可就把整曲标为已验收。

场景多了以后，按“分类 → 话题与意图 → 少量卡片 → 关联曲子”读取。无需把上千个场景塞进一次对话，也无需数据库。新增卡片后用脚本重建索引与计数：

```bash
python3 scripts/scenes.py build
python3 scripts/scenes.py check
python3 scripts/scenes.py search "红包 不想收" --category 红包与送礼
```

命令在仓库目录运行，需要 Python 3.9+；不运行脚本也可以直接浏览 Markdown 分类页。检索按词面排序，只给候选，是否适用仍要读条件。

抓取的原文与片段先放[本地素材库](materials/README.md)，阅读版去掉来源杂项，出处单列，评估后再进入曲子库；素材数量不计入曲目数量。

想贡献素材，可以说：

```text
给 say-skill 增加曲子素材：[场景、原话、你喜欢的表达和原因]。
先看看已有曲目，是补样例还是新机制。保留来源，不把它写成万能话术。
```

也可以让 AI 主动找材料：

```text
给 say-skill 补充“拒绝家庭聚餐”的文章素材。
用可用的 RedFox 搜索，再抓取并阅读正文；只保留有具体处境和对话的段落。
先修订已有场景，缺少对应方法再新增曲子。保留原场景、出处、改写与取舍。
抓不到正文就记为线索，不根据标题编例子。
```

[正文采集流程](references/article-intake.md)说明 RedFox、atm 的接法与失败处理。它们是素材维护时的可选工具，普通回复不依赖它们。搜索热度只帮助找文章，不用来判断话说得好不好。

具体模板、去重方法、验收方式及可交给其他 AI 的贡献指令见 [CONTRIBUTING.md](CONTRIBUTING.md)。普通使用不会自动保存私人对话。

## 想找借口，也可以直接说

```text
我不想参加这次聚餐，也不想告诉对方真实原因。
帮我找个低细节的托辞，语气客气一点；对方问“那改天呢”也帮我接一句。
```

会优先给不展开私事的说法，考虑追问和改期，不替你安排出差、生病或下次请客。已经答应过、对方订了位等情况，也请一起说，避免轻巧推辞反而让人难办。

资料、书单及实际阅读范围见[来源记录](references/sources.md)。验收以私事没暴露、决定能完成、关系有照顾、后面不用不断圆话为标准，模型试用与人工语感认可分开记录；见[第一批验证](tests/validation-2026-10-01.md)和[多层判断曲子验证](tests/multi-layer-tunes-2026-10-02.md)。

## noai 怎么用

say-skill 先把意思说对，再检查是否自然。已安装 `noai-skill` 时会读取并使用它做表达检查；没有安装也可以依靠包内检查正常工作，不需要额外 API Key。

say 将关系、目的、公开范围、语气和禁止增加的承诺随草稿交给 noai。回应办法不合适时先返回 say 重写，不能只换软词。

检查会去掉空泛、僵硬或油腻的表达，同时保留有作用的感谢和礼貌，不把明确拒绝改软。普通使用只给消息，不附一份长篇审稿报告。

## 安装

仓库、Skill 名称和安装目录统一为 `say-skill`，调用方式为 `$say-skill`。历史测试保留运行时的旧名称与路径，不作为当前安装指令。

把**整个仓库目录**安装到工具支持的 Skills 目录，不能只复制 `SKILL.md`，因为入口需要读取曲子库等相对路径资源。

例如，使用已有 `~/.agents/skills/` 目录的 Codex 环境，可在终端运行：

```bash
mkdir -p ~/.agents/skills
git clone https://github.com/fenming-ai/say-skill.git ~/.agents/skills/say-skill
```

目标已存在时先保留个人修改、比较版本，不直接删除或覆盖。其他工具按其实际 Skills 目录安装。

也可以把以下指令交给有文件访问能力的 AI：

```text
请把 https://github.com/fenming-ai/say-skill 的完整仓库安装到本工具的 Skills 目录。
先确认本工具支持的安装位置。目标已存在时保留个人修改，不直接覆盖。
安装后回读 SKILL.md 和 tunes/README.md，确认所有相对引用可访问。
不要只保存 SKILL.md，也不要声称安装了并不存在的 noai-skill。
```

新开对话，明确调用 `$say-skill` 并试一条新场景。检查本轮是否实际读取了入口和相关曲目；仅回答“我已使用”不算加载证据。

## 写得不对，直接纠正

- “我已经决定不去，不要留商量余地。”
- “删掉你替我编的理由，也别补别的。”
- “保留感谢，但不要一段话谢三次。”
- “我们还没那么熟，别写得这么亲昵。”
- “这是我平时会说的话：[例句]。参考语气，不照搬事实。”

想让偏好以后继续生效，明确要求保存到自己的安装副本，并保留旧版；不要把私人事实提交到公共曲子库。本地个性化后升级，应比较并保留自己的修改。

## 效果怎么判断

用[验收案例](tests/cases.md)换场景检查：意思有没有变、有没有编造、拒绝是否清楚、语气是否适合关系。曲目数量不等于效果；没有实际人审与反馈，就不标记为已验收，也不承诺对方一定接受。

它帮助表达，不保证恋爱成功，也不能用一句话消除欺凌。遇到孩子受欺负，会帮助组织支持与求助的话，不能取代成年人的保护行动。
