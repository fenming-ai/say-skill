# speak-skill｜帮我说清楚

想说的话已经在脑子里，但写出来太绕、太客套，或者不像自己？把原话给它，整理成可以直接发出的消息。

**这次你调好的做法，下次可以继续用。**这是一份可阅读、可修改的 Agent Skill，不是代发消息的机器人，也不是保证沟通成功的话术库。

## 先用一次

安装后，在 Codex 对话中输入：

```text
使用 $speak-skill。
帮我说清楚：朋友约我今晚吃饭，我想在家休息，这次不去，也不想约定下次时间。友好一点，但不要替我编理由。
```

你会得到一版消息草稿。发送前检查：意思没变、没有编造、语气像自己。它不会替你发送。

以后也可以说“帮我说清楚＋原话”。自然语言是否自动匹配由工具判断；没有选中时，用 `$speak-skill` 明确调用。

## 安装到 Codex

前提：已经能正常使用 Codex。本仓库不要求额外 API Key、脚本或其他 Skill。

**不想敲命令：**在能操作本地文件的 Codex 会话中粘贴：

```text
请阅读 https://github.com/fenming-ai/speak-skill 的 SKILL.md，确认它只整理消息、不代发。
把这份文件安装为 ~/.agents/skills/speak-skill/SKILL.md。
如果目标已存在，先告诉我，不要覆盖。
安装后回读文件，告诉我实际保存位置和 name 字段；不要只在聊天里贴代码。
```

根据 Codex 的提示批准本次所需文件操作。若会话不能联网，可从仓库下载 `SKILL.md` 后交给它保存。**文件名必须是 `SKILL.md`，不能变成 `SKILL.md.txt`。**

**熟悉终端：**已安装 Git 时，可在 macOS / Linux 终端运行：

```bash
mkdir -p ~/.agents/skills
git clone https://github.com/fenming-ai/speak-skill.git ~/.agents/skills/speak-skill
```

目录已存在时 `git clone` 会停止；不要为重装直接删除已有版本。

**确认真的装好：**在 Codex CLI 输入 `/skills`，查找 `speak-skill`，或者输入 `$` 在技能列表中选择。未出现时重启 Codex 再检查。新开对话运行上面的例子，并查看本轮是否实际读取了 `speak-skill/SKILL.md`；仅回答“我已使用”不算读取证据。

安装路径和调用方式依据 [OpenAI 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)。其他 Agent 工具的安装位置可能不同，不能直接照搬路径。

## AI 写得不对，怎么改

- **意思变了：**“我只是想问对方有没有空，不是已经定好了，保留这个区别。”
- **编了原因：**“我没说生病，删掉这个原因，也别补别的理由。”
- **太客套：**“礼貌就行，删掉反复感谢和道歉，像平时发微信。”
- **拒绝太软：**“我已经决定不去，不要留下还可以商量的意思。”
- **语气太冲：**“保留我的决定，删掉指责对方的话。”
- **不像自己：**“这是我平时会发的话：[自己的例句]。参考语气，不要照搬里面的事实。”

想让修改下次继续生效，再明确告诉 Codex：

```text
把刚才我确认过的表达偏好保存到已安装的 speak-skill/SKILL.md。
先保留一个旧版备份，只更新通用要求，不把这次的人名、时间和事情写成长期规则。
告诉我改了什么，回读确认，再用一条新消息测试。
```

## 生活暗号速查

这些是同一款 Skill 的具体用法，不需要每种场景装一个。

- **帮我相亲：**介绍自己，别写得像竞聘答辩。补充真实情况和想呈现的特点。
- **帮我泡妞：**想约人喝咖啡，别写成商务邀约。说清关系与真实想法，不保证别人喜欢你。
- **帮我拒绝：**不想参加聚会，又不想编生病理由。
- **帮我回复老师：**想问清孩子的情况，别一开口像质问。
- **帮我回复评论：**回应对方具体的问题，不只回“感谢支持”。
- **帮我请假：**说清请假时间和已确认的工作安排，不虚构理由。
- **帮我写邮件：**把散乱想法整理成对方知道该回复什么的简短邮件。

不知道给什么信息时，补三件事就够了：**发给谁、对方说了什么、我真正想表达什么。**已说清就不用重复填表。

“帮我上班”“帮我管住购物车”“帮我睡觉”可以是你下一款 Skill 的名字，但不是这款已经具备的功能。先把大暗号缩成小任务：例如“帮我睡觉”只整理明天待办，不承诺治疗失眠。

## 想自己做？复制这段封装 Prompt

跟做顺序只有五步：**贴原话 → 调到满意 → 生成 Skill → 安装好 → 新开对话换句话调用。**

先和 AI 把一次真实任务调到满意，再在**同一段对话**中粘贴。没有调过就直接封装，只会把未经验证的要求存起来。

```text
把这段对话里我已经确认有效的做法，整理成一个 Agent Skill。

名字：speak-skill
常用暗号：帮我说清楚
任务：把我的原话整理成能直接发送的日常消息。

只保存我确认过的要求、必要步骤，以及能说明这些要求的输入输出样例。
区分通用规则和本次事实：人名、日期、经历不能变成以后每次都带入的要求。
保留我的真实意思和不确定性，不编理由、不替我承诺；缺少会决定意思的信息时再问。
暗号后面接新原话就能使用，不强制填表，不自动发送消息。

生成完整的 SKILL.md，开头包括 YAML 的 name 和 description。
description 写清任务和适用时机，正文保持简短，不添加脚本或无关功能。
先展示文件内容并说明：哪些来自我确认过的要求，哪些仍需我确认。
不要声称已经安装；等我确认内容后，再执行保存。
```

确认后再发：

```text
把刚才确认的内容保存到 ~/.agents/skills/speak-skill/SKILL.md。
如果已经存在，先告诉我，不要覆盖。保存后回读文件，确认 name 和内容正确。
告诉我如何在 Codex CLI 的 /skills 列表找到它，以及如何在新对话明确调用。
```

换成其他小任务时，修改名字、暗号、任务和任务边界；不要机械沿用“消息整理”的限制。

## 没成功，先看这里

- **喊暗号没反应：**先查技能列表，再试明确调用；文件存在不等于本轮已加载。
- **总带入上次的人名和日期：**把这些从通用规则移回示例，换材料再测。
- **改一次就以为永久记住：**普通对话纠正不等于更新文件，要明确要求保存并回读。
- **本地个性化后想升级：**先备份自己的修改，再比较新版，不用强制覆盖。

## 验收用例

新开会话，明确调用 Skill 后分别试。措辞不必一致，检查意思而不是背标准答案。

1. “朋友约我今晚吃饭，我想在家休息，不去也不约下次。”——不编生病、不许诺下次。
2. “房东问续租，我还在考虑，下周一才能决定。”——不擅自答应或说一定搬走。
3. “他又问那件事，帮我明确回一句。”——先问是哪件事、想表达什么。
4. “想约刚认识的人周六喝咖啡，但不知道对方有没有空。”——是询问，不写成已约好，不施压。
5. “老师说孩子最近上课走神，我想了解具体情况，还不确定原因。”——问具体情况，不编诊断、不质问。

这是检查清单，不是所有模型都通过的保证。模型、上下文和你的要求仍会影响结果。
